# Kickstarter 数据集精简分析

> 数据核对日期：2026-09-23  
> Kaggle：<https://www.kaggle.com/datasets/domingosun/kickstarter-dataset-629147-projects-may-2025>  
> 主文件：`Kickstarter Full Campaigns_694062_25_April_2026.csv`

## 1. 结论

该数据集适合做：

- 众筹项目成功或失败预测
- 最终筹资金额预测
- 目标金额、上线时间和项目周期优化
- 项目文本与营销表达分析
- 发起人分层与平台客户运营
- 品类、国家、平台推荐和风险治理分析

它的主要优势是规模大、字段全、更新时间较近，而且 Kaggle 使用量相对较低。主要限制是金额极度右偏、缺少每日筹资轨迹，并且部分字段只有在项目结束后才知道，不能用于预测模型。

## 2. 数据集是什么

该数据集记录 Kickstarter 平台上的 **项目级众筹数据**。每一行代表一个项目，汇总了项目的创建、上线、截止、融资结果、发起人、类别、地区、文本和平台推荐信息。

| 项目 | 内容 |
|---|---|
| 数据规模 | 694,062 行 × 43 列 |
| 文件大小 | 约 455 MB |
| 数据时效 | 主文件覆盖至 2026 年 4 月左右 |
| 已完成项目 | 成功 297,538；失败 307,093 |
| 已完成项目成功率 | 49.21% |
| 2024 年以后已完成项目 | 69,865，成功率 64.87% |
| 唯一发起人 ID | 507,115 |
| Kaggle 使用量 | 758 downloads、4,348 views、1 notebook |
| 分析单位 | Kickstarter 项目，不是用户、交易或每日记录 |

推荐分析样本：

- 做成功/失败分类时，只保留 `successful` 和 `failed`。
- 做近期趋势分析时，优先使用 2024 年以后的项目，约 80,446 行。
- 做跨国金额比较时，统一使用 `usd_pledged`。
- 做时间验证时，按年份切分训练、验证和测试集，避免未来信息泄漏。

## 3. 对本周作业的适配性

本周作业要求包括：

1. 报告 shape、dtypes 和 missing values。
2. 为每一列说明 nominal、ordinal、interval、ratio，以及 discrete 或 continuous。
3. 最多选择三个变量分析关系，并给出统计量和图形。
4. 写 150–200 词说明发现及其对后续建模的意义。
5. 小组成员必须使用不同变量。

**适配结论：非常适合。** 数据集列数和类型足够丰富，金额、类别、时间、文本和地区变量都可用于统计描述与可视化，能够自然形成五位成员互不重复的变量组合。

### 五人变量划分

| 成员 | 不重复变量 | 可分析的关系 |
|---|---|---|
| A | `state`, `launched_at`, `deadline` | 项目结果、上线时间和持续周期 |
| B | `category_parent_name`, `country`, `location_type` | 类别、国家和项目所在地类型 |
| C | `goal`, `usd_pledged`, `backers_count` | 目标金额、实际筹资和支持人数 |
| D | `staff_pick`, `spotlight`, `created_at` | 平台推荐状态和创建时间 |
| E | `name`, `blurb`, `creator_id` | 文本特征与发起人项目行为 |

该划分满足“不同成员使用不同变量”的要求。每位成员都可以完成：

- 数据类型和属性类型表
- 缺失值检查
- 描述性统计
- 2–3 张关系图
- 150–200 词总结

## 4. 关键字段

只保留可以直接支持后续分析方向的字段。

### 4.1 结果与目标变量

| 字段 | 类型 | 分析用途 |
|---|---|---|
| `state` | Nominal / Discrete | 成功、失败、取消等分类；分类模型目标 |
| `usd_pledged` | Ratio / Continuous | 最终筹资金额；回归模型目标 |
| `pledged` | Ratio / Continuous | 本地货币筹资额，不适合作跨国直接比较 |
| `backers_count` | Ratio / Discrete | 支持人数；结果变量或规模指标 |
| `percent_funded` | Ratio / Continuous | 完成比例；项目结果的强代理变量 |

注意：`pledged`、`usd_pledged`、`backers_count` 和 `percent_funded` 都是项目进行中或结束后的结果。预测项目能否成功时，它们只能作为目标或评估结果，不能同时作为特征。

### 4.2 项目设计与融资条件

| 字段 | 类型 | 分析用途 |
|---|---|---|
| `goal` | Ratio / Continuous | 目标金额；成功概率、筹资金额和定价策略核心变量 |
| `campaign_duration_days` | Ratio / Continuous | 由 `deadline - launched_at` 计算；研究项目周期 |
| `name` | Nominal / Text | 文本长度、词频、TF-IDF 和关键词分析 |
| `blurb` | Nominal / Text | 项目简介主题、情感、长度和文案效果分析 |
| `category_name` | Nominal / Discrete | 具体品类分析 |
| `category_parent_name` | Nominal / Discrete | 一级品类；更适合建模，类别更稳定、样本更充足 |

### 4.3 时间和市场背景

| 字段 | 类型 | 分析用途 |
|---|---|---|
| `created_at` | Interval / Discrete | 项目创建到上线的筹备周期 |
| `launched_at` | Interval / Discrete | 年份、季度、月份、星期和季节趋势 |
| `deadline` | Interval / Discrete | 截止时间与项目持续时间 |
| `country` | Nominal / Discrete | 国家和市场比较 |
| `location_type` | Nominal / Discrete | 城市、城镇等项目所在地类型 |
| `location_name` | Nominal / Discrete | 城市级市场分析；类别较细，建模前需编码 |

### 4.4 发起人与平台运营

| 字段 | 类型 | 分析用途 |
|---|---|---|
| `creator_id` | Nominal / Discrete | 构造发起人历史项目数、成功率和平均筹资 |
| `staff_pick` | Nominal / Discrete | 平台编辑推荐；研究推荐资源效果 |
| `spotlight` | Nominal / Discrete | 平台曝光状态；研究流量分配与结果 |
| `currency` | Nominal / Discrete | 识别原始货币和汇率处理范围 |

### 4.5 建模时必须谨慎处理的字段

| 字段 | 问题 |
|---|---|
| `state_changed_at` | 项目结束时间，预测时不可用 |
| `profile_state` | 可能与项目结果同步发生 |
| `profile_blurb` | 缺失率约 85%，不适合作为主变量 |
| `category_id` | 缺失约 19%，优先使用类别名称或按 ID 映射 |
| `percent_funded` | 由结果直接计算，存在严重结果变量泄漏 |

## 5. 数据质量重点

- 字符串 19 列、整数 15 列、浮点数 7 列、布尔值 2 列。
- 主要缺失：`profile_blurb` 85.11%、`category_id/category_name` 18.97%、`usd_pledged` 1.64%、`launched_at` 1.11%、`deadline` 1.08%。
- `launched_at` 和 `deadline` 存在无效时间戳，应清理 1970 年等异常值。
- 金额字段存在极端值和少量负值，适合对数变换、分位数和稳健统计。
- `goal` 和 `pledged` 是本地货币，跨国比较必须使用美元字段。
- `staff_pick` 和 `spotlight` 存在选择偏差及反向因果，不能简单解释为因果效应。

## 6. 能支持哪些商业决策

| 商业问题 | 分析目标 | 推荐方法 | 决策或产出 |
|---|---|---|---|
| 哪些项目值得优先推荐或辅导？ | 预测成功概率 | Logistic Regression、Random Forest、Gradient Boosting | 项目评分、推荐优先级、干预名单 |
| 目标金额应设为多少？ | 研究 Goal 与成功率及筹资额的关系 | 分桶、Logistic Regression、概率曲线、敏感性分析 | 品类推荐区间、过高目标预警 |
| 何时上线、持续多久更好？ | 时间与项目周期优化 | 时间趋势、分组比较、季节分解、控制回归 | 上线日历、推荐周期、流量排期 |
| 哪些品类和市场值得投入？ | 品类与国家增长分析 | 交叉表、热力图、增长率、聚类 | 市场优先级、营销预算建议 |
| 平台推荐位应分配给谁？ | 评估 Staff Pick / Spotlight 与结果的关系 | 倾向得分匹配、分层、控制回归 | 推荐规则、资源 ROI 代理值 |
| 哪些发起人值得重点合作？ | 发起人生命周期和分层 | RFM、K-Means、成功率评分 | 高价值名单、新手扶持方案 |
| 项目应如何包装和表达？ | 文本与营销效果分析 | 词频、TF-IDF、主题模型、情感分析 | 高成功关键词、文案模板 |
| 哪些项目存在取消或失败风险？ | 风险识别 | 多分类、异常检测、风险评分 | 预警清单、审核优先级 |
| 营销服务公司应向谁销售？ | 客户潜力识别 | 分群、成功概率、需求画像 | 潜客名单、服务套餐建议 |

核心业务价值不是单纯追求模型准确率，而是把结果转换成：

- 哪些项目应获得资源
- 哪些项目需要提前预警
- 发起人应如何设定目标和上线时间
- 平台应如何分配推荐位和预算
- 哪些品类、国家和发起人值得长期投入

## 7. 可行研究方向与方法

### 7.1 项目成功预测与资源优先级

- 目标：`state = successful / failed`
- 特征：`goal`、品类、国家、上线月/季度/星期、持续天数、文本特征、发起人历史、`staff_pick`、`spotlight`
- 方法：Logistic Regression、Decision Tree、Random Forest、Gradient Boosting
- 评估：ROC-AUC、PR-AUC、Precision、Recall、F1、Calibration、Top-Decile Lift

### 7.2 筹资金额预测

- 目标：`log(1 + usd_pledged)`
- 方法：多元回归、Ridge、Lasso、Random Forest、Gradient Boosting
- 评估：MAE、RMSE、RMSLE、R² 和分位数误差

### 7.3 目标金额与成功概率

- 方法：Goal 分桶、品类与国家分层、Logistic Regression、决策树
- 产出：成功概率曲线、推荐目标区间、目标金额审核规则

### 7.4 时间、周期与季节效应

- 方法：趋势分析、季节分解、分组比较、控制类别和目标金额的回归
- 产出：类别上线日历、最佳持续周期、平台活动排期

### 7.5 文本与营销文案

- 方法：文本长度、词频、TF-IDF、主题模型、情感分析
- 产出：高成功率关键词、失败文案特征、品类专属模板

### 7.6 发起人分层与 CRM

- 基于 `creator_id` 构造历史项目数、成功率、平均筹资、首次和最近发起时间
- 方法：RFM、K-Means、层次聚类、评分模型
- 产出：高价值发起人、成长型发起人、高风险新发起人

### 7.7 平台推荐与因果分析

- 方法：倾向得分匹配、分层、控制回归、平均处理效应
- 风险：平台不是随机推荐，推荐和成功可能互为因果
- 产出：推荐资源优先规则、推荐效果区间和扶持策略

### 7.8 品类、国家和风险治理

- 方法：品类 × 国家交叉分析、增长率、聚类、多分类和异常检测
- 产出：市场扩张优先级、地区营销策略、风险预警规则

## 10. 适用性判断

| 维度 | 判断 |
|---|---|
| 本周个人作业 | 很适合，数据规模、类型、缺失值和变量选择空间都充足 |
| 五人不同变量要求 | 很适合，可以形成五组互不重复且仍有分析价值的变量 |
| 描述性分析 | 很适合，类别、金额、时间、地区均可视化 |
| 预测建模 | 很适合，可做分类和回归 |
| 文本分析 | 较适合，有 `name` 和 `blurb`，但没有完整项目正文 |
| 因果分析 | 有条件适合，推荐变量可用匹配或控制方法，但不能轻易下因果结论 |
| 时效性 | 较好，数据覆盖至 2026 年 4 月左右 |
| 撞题风险 | 相对低，当前 Kaggle 使用量较少 |

**最终判断：可以作为首选数据集。** 最稳妥的项目路线是“**项目成功预测 + 目标金额优化 + 平台资源分配**”，再用时间和文本分析作为补充。必须排除 `pledged`、`usd_pledged`、`backers_count`、`percent_funded`、`state_changed_at` 和 `profile_state` 等结果变量，避免模型产生结果变量泄漏。
