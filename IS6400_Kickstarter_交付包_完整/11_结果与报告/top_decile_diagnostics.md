# top-10% 高分的诊断（回应“99.2% 是否偏高”）

- 测试集：**100,469** 行（2023+），基准成功率 **64.41%**
- 模型：HistGB（我们切分），阈值 0.39（阈值只影响 Acc/Prec/Recall/F1，**不影响** 按分数排序的 top-decile）

> 预测概率与实际命中率高度接近（校准良好），说明不是“分数虚高”。

## 3) 对照基准：不用模型，只用简单规则排序

| 排序规则 | top-10% 实际成功率 | lift |
| --- | ---: | ---: |
| 随机 / 全体 | 64.41% | 1.00 |
| 目标金额升序（越小越前） | 91.10% | 1.41 |
| 时长接近 14 天优先 | 86.39% | 1.34 |
| **模型分数** | 99.24% | 1.54 |

> 关键：若“只按目标金额升序”就能拿到很高命中率，则说明 top-decile 高度依赖“低目标”这一简单信号；模型的价值要看它相对该基线的**增量**。

## 4) 与“去掉履历特征（creator_*）”的消融对照

| 特征集 | AUC | Brier | top-10% 实际成功率 |
| --- | ---: | ---: | ---: |
| 全特征（20 个） | 0.8823 | 0.1316 | 99.24% |
| 去掉 `creator_*` | **0.8488** | **0.1467** | 见 s0 输出 |

> 去掉履历后 AUC 下降约 0.034，但 top-decile 仍约 97% → 高分**不是**履历泄漏造成的。

## 结论

1. **不是 bug、也不是概率虚高**：每个切点上“平均预测概率 ≈ 实际命中率”（如 top10%：98.45% vs 99.24%），说明模型给出的概率是校准的；
2. **不是履历泄漏**：去掉 `creator_*` 后 AUC 0.8823 → 0.8488，top-10% 仅降到约 97%（仍远高于 64.41%）；
3. **但 top-decile 高度集中**：92% 来自 games(70.4%)+comics(21.5%)，89% 落在 ≤5k 的两档，本质是“2023 年后（基准率 64.4%）的小目标、高成功率品类项目”；
4. **模型的真实增量**：只按“目标金额最小”排序的 top-10% 已有 **91.10%**，模型是 **99.24%**，即**+8.1pp**；只按时长排序 86.39%。所以汇报时应写成“**相对简单规则提升 8.1pp**”，而不是只报“99% vs 64%”。

## 报告里的建议措辞

> “在 2023 年之后的测试集上，模型选出的前 10% 项目实际成功率 99.2%（总体 64.4%）；作为对照，仅按目标金额最小排序可得到 91.1%、仅按时长排序 86.4%，因此模型的增量价值为 **+8.1pp**。该档位高度集中在 Games/Comics 的低目标项目，说明模型识别的是‘高概率成功段’，但不能据此推断其商业价值同样高（见 business value 一节）。”
