# S1 解释性：让 HistGB 变得可讲

> 生成：`python 09_分析脚本/_interpretability.py`（单线程约 6 分钟）
> 流程：加载 `model_histgb_ours.joblib` → **验证测试集 AUC = 0.8823** → 置换重要性（20,000 抽样 × 5 次）→ 7 条 PDP
> 产物：`s1_lr_coefficients.csv`、`s1_permutation_importance.csv`、`s1_pdp_<feature>.csv`、`s1_pdp_summary.csv`、`s1_direction_check.csv`、`s1_interpretability.json`

## 一、为什么需要这一层

HistGB 是 **250 棵 × ≤31 叶的加性树集成**（`max_iter=250, lr=0.08, max_leaf_nodes=31, l2=1.0`），预测为对数几率上 250 棵树求和：

- 没有可读参数：最多约 **7,750 个叶子值** + 路径分裂阈值；
- 效应依赖上下文：不存在"目标金额的系数"；
- 方向会翻转：同一特征在不同区域可反向；
- **sklearn 的 HistGB 连 `feature_importances_` 都不提供**。

但它不是纯黑箱——log-odds 上严格可加（`Σ 树 = logit(P)`），所以下面三件事都成立。

| 特征 | 网格范围 | 边际概率区间 | 首→尾变化 | 与 LR 方向 |

| `m_log_goal_usd` | 低 → 高 | 83.6% ↔ 45.5% | **−38.1pp** | 一致 |
| `creator_previous_count` | 0 → 多 | 58.0% ↔ 88.7% | **+30.7pp** | 一致 |
| `prep_days` | 短 → 长 | 48.6% ↔ 69.6% | +18.4pp | 一致 |

| `m_blurb_len` | 短 → 长 | 63.2% ↔ 66.0% | **+2.5pp** | 一致 |
| `m_name_len` | 短 → 长 | 64.7% ↔ 65.1% | +0.3pp | 一致 |
| `creator_prev_success_rate` | 0 → 1 | 67.4% 附近 | **≈0** | **不一致** |

## 五、三个可以写进报告的发现

**1. "简介越长成功率越低（−13.3pp）"是构成效应，不是模型行为 —— 此前口头结论撤回。**
模型里 blurb 长度的边际效应是 **+2.5pp**（正向但很小），置换重要性只有 **0.34%**。原始分组对比里那个负号来自品类与目标金额的构成差异（长文案集中在高目标/低成功率品类）。正确表述：**在本模型中，文案长度几乎不影响预测；此前的负相关是混杂所致。**

**2. `creator_prev_success_rate` 是条件效应。**
置换重要性 9.1%（很高）但 PDP 几乎平（≈0）⇒ 它的作用依附于其他特征（交互），单看边际看不出来。这是"置换重要性 ≠ 方向"的标准案例，也说明**不能只靠单一全局指标下结论**。

**3. 两条主梁 + 两个第二梯队。**
履历（52.4%）+ 目标金额（19.7%）= **72%**；准备天数、品类子类、时长是第二梯队；文本长度几乎不影响。这与"评分卡里目标档 × 时长档 × 品类决定 91pp 差异"的业务结论方向一致。

## 六、局限

- PDP 是**边际**（对其余特征取平均），看到的是"平均效应"，交互效应被抹平（见发现 2）；
- 置换重要性在**相关特征间会分摊**（`creator_previous_count` 与 `creator_prev_success_rate` 高度相关，两者的占比不宜当作独立贡献相加）；
- LR 是 L2 惩罚模型，系数是收缩后的，**不能直接构造置信区间**做显著性检验；
- 环境未安装 `shap`，未做 TreeSHAP 逐行归因（树模型的 SHAP 是精确的，属可补齐项）；
- 置换重要性 = **预测贡献**，不是因果效应。
