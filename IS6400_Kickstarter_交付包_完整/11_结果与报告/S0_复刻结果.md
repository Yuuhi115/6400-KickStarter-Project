# S0 复刻结果：全量口径 vs 组员 pilot

> 运行：`python replicate_pilot.py --data full --split pilot --rf-trees 150 --tag full_pilot_v2`
> 数据：`08_建模就绪数据/ks_model_ready_v1.parquet`（可建模 604,629 行）
> 切分（复刻组员）：train `yr ≤ 2019` = 410,919｜val `2020–2022` = 93,241｜test `> 2022` = **100,469**
> 基准率：train 42.90%｜test **64.41%**
> 输出：`s0_metrics_full_pilot_v2.csv`、`s0_calibration_full_pilot_v2.csv`、`s0_stability_full_pilot_v2.csv`、`s0_summary_full_pilot_v2.json`

## 一、结论

**全量口径复刻成功，且优于组员 10% 样本的 pilot。** 三条验收线全部达成：

| 验收线 | 目标 | 实测（HistGB） | 判定 |
| --- | --- | --- | --- |
| 测试集 ROC-AUC | ≥ 0.85 | **0.8799** | ✅ |
| Top-Decile Lift | ≥ 1.5 | **1.5401** | ✅ |
| Brier Score | ≤ 0.15 | **0.1330** | ✅ |

## 四、口径替换确实生效（这是与组员结果不同的原因）

| 组员 pilot | 我们 | 依据 |
| --- | --- | --- |
| `goal` / `log1p(goal)`（混币种） | `m_log_goal_usd` | 非 USD 占 31.26%，>50k 档曾高估 6.6pp |
| `campaign_duration_days`（截断） | `m_dur_days_exact` | 旧口径 41.79% 行有截断误差 |
| 文本长度 `fillna("")` | `m_name_len`/`m_blurb_len`/`m_blurb_words` | 缺失感知 |
| `creator_previous_*`（仅 10% 样本内算） | `creator_rank−1` + `creator_prev_success_rate`（全量 point-in-time） | 履历更完整 |
| `category_name` / `country` | `subcategory_key` / `country_final` | 已归并大小写、统一口径 |

> 注：v1 那次运行（`full_pilot`）发现 `launched_at` 被当作纳秒解析，导致 `prep_days` 被污染（约 −15000 天）；修正后 HistGB 从 0.8684 → **0.8799**、Brier 0.1468 → **0.1330**，说明"准备天数"确实携带真实信号。旧结果作废，以 `full_pilot_v2` 为准。

## 五、⚠️ 一个需要继续查的疑点

**Top-10% 实际成功率 99.20%（AUC 0.88）偏高。** 虽然口径已严格（时间切分、结果类字段全排除），但仍需排除隐性信息，下一步专做消融：

1. **去 `prep_days`**（`--no-prep-days`）：准备天数 = 上线 − 创建，若它隐含了结果信息（例如审核被反复推迟的项目更可能失败/成功），会虚高；
2. **去履历特征**（`creator_*`）：全量 point-in-time 是真历史，理论上安全，但要验证；
3. **USD-only 子样本**（`--data usd`）：稳健性；
4. **我们的切分协议**（`--split ours`，train ≤2022 / test ≥2023）：与交付数据的 `m_split` 一致。

## 六、下一步（按优先级）

- [ ] 消融 A：`--no-prep-days`（泄漏检查，最高优先）
- [ ] 消融 B：`--split ours`（换成我们的切分协议）
- [ ] 消融 C：`--data usd`（USD-only 稳健性）
