## 三、使用时的四条硬规则

1. **10 个泄漏列一律剔除**：`pledged`、`usd_pledged`、`backers_count`、`percent_funded`、`converted_pledged_amount`、`spotlight`、`profile_state`、`staff_pick`、`state_changed_at`、`profile_state_changed_at`。混入后测试集 AUC = 1.0000，是假象。
2. **只保留终态**：`state` ∈ {successful, failed}；`live` / `submitted` / `started` 属右删失，`canceled` / `suspended` 口径特殊，均不计入成功率。
3. **时间列要混合解析**：`created_at` 与 `deadline` 同时存在字符串与 epoch 两种编码；`launched_at` 为 epoch 秒且 11,405 行为 1970 无效值，需先剔除再算时长。
4. **文本只用 name / blurb**：`profile_blurb` 缺失 85.11%，`profile_name` 缺失 5.23% 且与 `name` 冗余。
