# 方法与预期模型说明

> **一句话**：用可解释的统计与机器学习方法，基于 60.5 万个已有明确结果的项目，训练一个
> **「上线前配置评分模型」**——发起人在上线前填写自己的配置，模型给出**达标概率**，并据此给出**金额、时长、文案**三项建议。
>
> 数据：`ks_clean.csv`（673,839 行 × 68 列；其中可建模 **604,629** 行）
> **选型纪律**：本文的选型理由**只来自数据结构与问题性质**，不用已跑出的指标倒推（"试出来分数高所以选它"是循环论证）。已跑出的数字集中在 §六。

---

## 一、我们要产出什么模型、用于什么

### 1.1 模型形态

| 项目 | 内容 |
| --- | --- |
| 模型类型 | 二元概率模型：`P(达标 = 1 \| 上线前配置)`，输出 0–1 的达标概率并做**概率校准** |
| 输入（全部为上线前已知信息） | 品类、目标金额、计划项目时长、国家/币种、标题与简介文案、是否二次发起 |
| 输出 | ① 该配置的**达标概率** + 同品类同档位的**历史基准与样本量**；② 金额/时长/文案的调整方向；③「达标概率 vs 成功时募资额」的权衡 |
| 配套模型 | 分位数回归（预测成功时募资额的中位/90 分位），用于双目标权衡 |

### 1.2 两个使用场景

1. **发起人侧（主）**：上线前的配置决策。例：某 Games 项目目标 $15,000、计划 30 天 → 给出达标概率与同档基准，并提示时长调整方向。
2. **平台侧（次）**：早期风险筛查与提示。用同一模型的概率排序，对高风险项目给出预警或资源倾斜建议。

### 1.3 明确**不做**的三件事

| 不做 | 原因 |
| --- | --- |
| ❌ 爆款预测 | 字段里没有流量 / 视频 / 社群 / 投放变量；爆款由受众与传播决定，数据里没有这些信号 |
| ❌ 因果推断（"把目标调低就能提升 X 个百分点"） | 观察性数据，且目标金额是发起人**预判需求后自定**的（内生性）——只能说关联与预测 |
| ❌ 给"人"打分 | 84% 的发起人一辈子只发起一次；给人打分既不可操作也有公平性问题。只给**配置**打分 |

### 1.4 最终交付物（三件）

1. **配置评分模型**（含概率校准与评估报告）；
2. **配置评分表**：品类 × 目标金额档 × 项目时长档 的达标率矩阵（只展示 n≥300 的格子，附成功时募资额中位数）；
3. **按品类的文案关键词面板**（品类内成功/失败导向词，附提及次数与品类内 lift）。

**「配置评分表」是什么、怎么读**——它就是**一张查表用的矩阵**：发起人拿自己的配置去查，立刻看到"历史上跟我配置相似的项目，达标率是多少、成功时通常募到多少"。

**行 = 目标金额档，列 = 项目时长档，格 = 达标率 %（样本量 n）**。以 Games 品类为例（真实数据）：

| 目标金额 \ 时长 | ≤14 天 | 15–21 天 | 22–30 天 | 46–60 天 |
| --- | ---: | ---: | ---: | ---: |
| ≤$1k | 93.6% (6,065) | 92.0% (5,270) | 80.4% (11,168) | 53.2% (1,203) |
| $5–10k | 80.4% (506) | 79.2% (1,305) | 55.4% (8,729) | 22.7% (1,296) |
| $10–20k | 70.6% (235) | 76.4% (794) | 50.5% (6,021) | 16.4% (958) |
| >$50k | 67.8% (143) | 76.9% (389) | 34.6% (3,106) | 6.8% (1,100) |

三处设计各有原因：

- **为什么品类单独成表（而不是也做成一个维度）**：品类不是发起人能改的，它是**条件**——桌游项目不会变成出版项目；真正能改的只有**金额与时长**，所以让它们做行与列，每个品类各有一张表。
- **为什么只展示 n≥300 的格子**：样本太少会读错。例：`$10–20k × ≤14 天` 只有 n=235、`$20–50k × ≤14 天` 只有 n=208，后者反而**高于**更便宜的档位，明显是噪声，不能当结论。
- **为什么附「成功时募资额中位数」**：只看达标率会把所有人推向"目标定 $1"。同一张表旁给出：

| 目标金额档 | 达标率 | 成功时中位募资 | 全部项目中位募资 |
| --- | ---: | ---: | ---: |
| ≤$1k | 84.4% | $1,797 | $1,347 |
| $10–20k | 49.2% | $29,845 | $9,242 |
| >$50k | 32.3% | **$119,325** | $2,329 |

注意最后两列：`>$50k` 档"**全部项目**中位募资"只有 $2,329，但"**成功项目**中位募资"是 $119,325——**用哪个数看，结论正好相反**，所以必须同时给出。

**它与模型的分工**：评分表是**历史基准（锚点，不含模型）**，让模型的输出有参照（"模型说 62%，同档历史基准 55%"）；模型是**个性化预测**（额外用上国家、发起人履历、文案等），并支持**反事实扫描**（固定项目、只改一个字段重跑）。使用流程：选品类 → 找到自己的金额行与时长列 → 看历史达标率与该档收益 → 再用反事实扫描拿个性化建议。

## 二、选用哪些模型

| 模型 | 层次 | 作用 |
| --- | --- | --- |
| **逻辑回归**（+ 标准化） | 解释 | 输出**优势比**——"某变量每 +1 个标准差，达标几率变成原来的几倍"；兼作校验器 |
| **单棵浅决策树**（depth 4–5） | 沟通 | 能读成人话的规则（"时长 X–Y 天且品类 Z → 达标率约 P"），不是为性能 |
| **随机森林** | 性能 + 重要性 | 抓非线性与交互；给出特征重要性排序，与系数、分箱结论互证 |
| **梯度提升**（HistGB） | 性能上限 | 作为"上限探针"，检验上线前可见信息到底能解释多少 |
| **KMeans**（对"配置"分群） | 分档 | 把连续的"金额 × 时长"空间切成可解释档位，供评分表使用 |

另外三件各管一段：**文本** 用 TF-IDF（要词级可解释）；**收益侧** 用分位数回归（重尾数据不能用均值）；**平台层面** 用 Holt-Winters / 指数平滑（月度序列）。

## 三、为什么选这些模型（先验理由）

### 3.1 先看数据长什么样

| # | 数据结构特征（字段本身的事实） | 它对模型提出的要求 |
| --- | --- | --- |
| S1 | 目标变量为**二值**，两类大致均衡（约 49% / 51%） | 适用分类模型；不需要重采样；**概率输出必须可信** |
| S2 | 样本量 **60 万级** | 参数估计稳定，简单模型已够用；但成本要可控（无 GPU、可复现） |
| S3 | 真正的**数值特征只有 8 个** | 维度来自类别与文本 → 重心在特征工程，而非"换更复杂的模型" |
| S4 | 类别变量基数差异大（品类 16 / 细分 218 / 地理国家 225 / 币种 15…） | 独热后维度中低但**互相相关** → 线性模型需正则化；树类对尺度不敏感 |
| S5 | 文本只有**一句话简介**（`blurb` 缺 0.02%、`name` 缺 0%），`profile_blurb` 缺 85.11% | 短文本 → 词袋 / TF-IDF 量级足够；且必须**词级可解释** |
| S6 | 目标金额与募款**极端重尾**（中位 $5,000，但存在 >$1M 的项目） | 线性模型需对数变换；树类天然不受尺度影响；**收益侧不能用均值** |
| S7 | 时间跨度 17 年，达标率逐年变动明显 | 评估必须**按时间外推**（不可随机切分）；模型需可重新校准 |
| S8 | 发起人历史极端偏斜：**84% 只发起 1 次**，最多 130 次 | 履历特征是"稀疏但强" → 需要能利用稀疏强信号，且要显式构造历史比值 |
| S9 | 缺失**非随机**（细分品类缺 18.97%、`profile_blurb` 缺 85.11%） | 模型要能处理缺失，或显式加入缺失指示列 |
| S10 | 关系形状不平凡：金额近似单调，**时长是非单调的**（中段存在低洼） | 需要能表达**非线性 / 分段常数**的模型；同时要能讲清形状 |
| S11 | 已知存在**交互**（同一金额档、不同品类走势不同） | 需要能自动捕捉交互的模型，或显式构造交互项 |
| S12 | 观察性数据，且目标金额由发起人自定（内生性） | 只能主张预测/关联 → 选可解释模型以**讲清方法学边界** |

**结构 → 模型**：S1+S2+S12 → 逻辑回归；S10+S11 → 树与集成；S3+S4+S9 → 特征工程与选择；S5 → TF-IDF；S6 → 分位数回归；S7 → 时间切分与校准；S8 → 履历特征。

### 3.2 逐个模型的理由

- **逻辑回归（解释层，放第一位）**：S1 设定与数据生成过程一致；S2 大样本下系数稳定；S12 + 产品需求要求输出**方向与倍数**（优势比），黑箱分数做不到；S4 的共线用 L1/L2 正则即可稳住；S9 的缺失可用指示列透明处理。它还**充当校验器**——优势比方向须与描述统计、分层检查一致，矛盾即说明特征工程或分层有错。局限（先验就承认）：S10/S11 说明存在非线性与交互，线性模型表达不了 → 必须有树类兜底。
- **单棵浅决策树**：S10 的分段形态与树的**分段常数**结构天然贴合；S4/S6 说明它不需变换；作用是**可读性**而非性能（深度限 4–5，用偏差换可解释性）。
- **随机森林**：S11 需要自动捕捉交互（树的分裂天然表达"金额 × 品类"）；S10 由分段结构承接；S3 数值特征少，无需复杂变换；S6 对重尾与异常值不敏感。另给**重要性排序**做互证。
- **梯度提升**：S3+S4+S9 的"中等维度 + 类别 + 缺失"表格结构正对它的设计；S2 说明 60 万行成本可接受。它的第二个作用是**划定上限**——若强模型也只能解释一部分，说明上线前可见信息本身就有限。
- **KMeans（分档层）**：可行动的连续变量只有少数几个（金额、时长），而评分表需要离散行列；配置空间是**低维连续**的，KMeans 简单稳定、簇中心可解读为"典型配置"。选它而非 DBSCAN/高斯混合：不规则形状簇在这里没有业务含义。先验就应承认：连续空间**很可能没有清晰边界** → 分群只能当**工具性分档**。
- **文本用 TF-IDF**：S5 是短文本，词袋级足够；产品要求"建议用/避免哪个词"，必须词级可解释；且无 GPU。字段选择同样来自结构——用 `blurb` / `name`（缺失极低），不用 `profile_blurb`。
- **收益侧用分位数回归**：S6 的重尾使均值被极值绑架 → 用中位 / 90 分位描述"成功时能募多少"。
- **平台层面用 Holt-Winters / 指数平滑**：S7 需要趋势判断；月度序列样本量有限（约 170 个月）→ 参数少的方法更稳。

### 3.3 为什么不用其他模型

| 候选 | 否决理由 |
| --- | --- |
| 深度学习（ANN / RNN） | 表格数据 + 50 万行，梯度提升已达同类上限；可解释性差、算力受限；W9 的 ANN 更适合时序/图像 |
| SVM | 50 万样本上核方法训练代价不可接受；解释性差 |
| KNN | 70 维独热 + 稀疏文本上距离度量失效；预测阶段近邻搜索也慢 |
| 朴素贝叶斯 | 特征独立假设在"金额 × 品类 × 时长"高度相关时明显违背；概率校准差 |
| XGBoost / LightGBM / CatBoost | 与 HistGB 功能重叠；额外依赖与调参、复现成本高；沙箱线程受限 |
| 纯阈值 / 规则模型 | 单变量阈值忽略交互（S11） |
| 生存分析 | 非终态记录没有结果信息；删失来自抓取时点而非真实事件时间 |
| 因果推断（DiD / IV / RDD） | 无外生变动；`goal` 内生；平台标记在结果之后 |
| 爆款分类 | 字段里没有流量/社群/投放变量；>$500k 正样本仅 4,130 个；平台标记列**在定义上**属于结果之后的变量 |
| SMOTE / 不平衡处理 | 两类本来就不失衡（约 49% / 51%）；真正的问题是时间漂移 |
| 情感分析 | 文本是项目简介而非评论，情感对"能否达标"没有明确机制，也无标注可验证 |

### 3.4 为什么要"多模型"，以及选对模型的四条标准

- 四个层次**目的不同**：解释（逻辑回归优势比）→ 沟通（浅树规则）→ 性能上限（随机森林/梯度提升）→ 分档（KMeans）；三视角（系数方向、特征重要性、分箱单调性）一致才敢写结论。
- **四条标准**：① 性能增量要值回可解释性代价（集成相对逻辑回归的 AUC 增量 ≥ **+0.02** 才值得换）；② 时间外稳定（滚动折、分年 AUC 无系统性下滑）；③ **概率必须校准**（工具输出概率，未校准的高 AUC 模型不可用）；④ 能翻译成业务动作（最终要落到金额档位、时长窗口、文案关键词）。

## 五、实现与评估要点（精简）

- **切分**：训练 `yr ≤ 2022`（502,975 行）/ 测试 `yr ≥ 2023`（100,469 行）；训练窗口内再切验证，用**滚动起点 6 折**（验证年 2017–2022）；**概率校准器只用验证集**拟合。
- **三条纪律**：不随机切分（达标率逐年漂移）；不把准确率当主指标（测试窗口的多数类基线就是 **0.6441**，"全猜成功"也有 64.4%）；特征选择与调参（含 RFE/PCA）**必须在训练窗口内**做。
- **指标**：AUC（排序）、PR-AUC（正类比例变化时更稳）、Brier（概率误差）、**校准曲线**（工具输出概率，必须校准）、十分位 lift（平台筛查用）；准确率仅作参考且须与基线并列。
- **验收清单**：☐ 切分严格按时间 ☐ 四基线齐备且多数类 0.6441 同表 ☐ 校准曲线接近对角线 ☐ 分年 AUC 无系统性下滑 ☐ 报"建议覆盖率" ☐ 保留泄漏对照实验
