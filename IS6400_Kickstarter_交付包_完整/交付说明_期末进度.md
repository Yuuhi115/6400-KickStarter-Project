## 〇、口径契约（先读这 12 行，防止混用四种概率）

本交付**同时存在四个不同对象的"成功概率"**，任何引用必须说明取的是哪一个：

| 名字 | 公式 | 取数对象 | 位置 |
| --- | --- | --- | --- |
| **P（个体概率）** | `predict_proba(该项目 18 个特征)` | **单个项目** | `model_histgb_ours.joblib` |
| **p_cell_mean（格均值）** | 格内逐项目 P 的平均 | 一个历史格 | `cells.parquet` |
| **p_profile（画像概率）** | `predict_proba(中位数+众数造的合成画像)` | **合成画像**，不对应任何真实项目 | `cells.parquet` |
| **rate（历史达标率）** | k / n，附 Wilson 95% CI | 观测事实 | `cells.parquet` |

三条必须记住的结论：

1. **画像 ≠ 格均值 ≠ 个体**：三者可差 10pp 以上。本交付的案例格是 **74.4% / 58.8% / 个体 76.6% / 历史 58.1%** 四个数并存。
2. **`p_weighted_q50_usd = p_cell_mean × median_payout_usd_success` 不是 E[Y]**，只是"概率 × 成功时中位数"的加权典型值；`exposure_usd = (1−p) × Q50` 也**不是期望损失**（我们没有成本/投入字段）。
3. **ΔP 是模型情景分差（描述性关联），不是因果收益**，且两次打分必须在**同一画像**口径下做。

唯一事实源：`11_结果与报告/cells.parquet`（450 格，上述四列并排）。**禁止**再从旧的 `decision_axes_cells.csv` 单独引用某一种口径。

## 二、方法（写报告可直接用）

### 2.1 数据三层

```
原始 694,062 × 43   (454.9 MB, Kaggle: domingosun/kickstarter-dataset-629147-projects-may-2025, MIT)
  ↓ 清洗（三层规则，已有）
清洗 673,839 × 81   (43 原始 + 38 派生；删除 20,223 行 = 2.91%)
  ↓ 建模就绪（本项目新增）
建模 673,839 × 92   (新增 11 个 m_* 列)
附录 USD-only 460,596 × 92（稳健性检验用）
```

**11 个建模列的用途**

| 列 | 解决什么 |
| --- | --- |
| `m_goal_usd` / `m_log_goal_usd` | 金额统一换算美元（非 USD 占 31.26%；不换会让 >50k 档达标率高估 6.6pp） |
| `m_goal_usd_ok` / `m_goal_usd_filled` / `m_currency_usd` | 标记可用性（含 USD 缺汇率的 7,836 行精确填充） |

| `m_split` | 预置时间切分（train ≤2022 / test ≥2023） |
| `m_is_modelable` | 可建模掩码（canceled 不算失败） |

三条要点：

1. **没有 92 列的 CSV**：导成 CSV 约 730 MB，且可空布尔/时间列会退化成字符串；parquet 保留类型且体积约为 CSV 的 1/3。
2. **92 列 ≠ 92 个特征**：实际入模 **18 个**（见 2.2）。其余是：标识符与 URL（`id`、`creator_id`、`profile_*_id`、各种 `_url`）、**10 个事后/泄漏列**（仅用于描述统计）、**9 个汇率审计列**（元数据）、以及若干冗余列（`goal_capped ≡ goal`、`creator_n_projects ≡ creator_rank`、`static_usd_rate_raw ≡ static_usd_rate`）。
3. 数据本体**不在 git、也不在进度包 zip 里**（231 MB 发不了），zip 只含 `README_建模数据说明.md` 与两个 `build_report*.json`；需要数据时可跑 `_build_model_ready.py` 重建，或走云盘传 parquet。

### 2.3 建模与验证

| 环节 | 设定 |
| --- | --- |
| 模型 | Dummy(prior) 基线、逻辑回归（liblinear, 3000 iter）、随机森林、**HistGB**（lr 0.08 / 250 iter / 31 leaves / l2 1.0） |
| 切分 | **按时间**：train ≤2020（443,693）/ val 2021–2022（60,467）/ test ≥2023（**100,469**）；另做过复刻组员的 ≤2019/2020–22/>2022 口径对照 |
| 阈值 | 只在**验证集**上用 181 点网格最大化 F1 → 0.39；原样套测试集 |
| 主指标 | ROC-AUC、PR-AUC、Brier、校准曲线、十分位 lift、分年稳定性；**准确率只作参考**（测试集多数类 64.41%） |
| 泄漏纪律 | 排除事后列；`goal` 内生 → 全程只主张关联，不做因果 |

### 2.4 三个决策轴的可操作化

```
business value = P(达标) × 同格「成功时中位募资」            ← 募资额代理（无收入/成本字段）
intervention   = max over {目标金额档, 时长档} [P(改后) − P(当前)]   ≥15pp 高 / 5–15 中 / <5 低
risk           = (1 − P) × 同格「成功时中位募资」；另标高危高赔格（达标率<10% 且 中位募资>$50k）
```

### 2.5 为什么这么做（每个关键决定都配一个反例）

| 决定 | 如果不这么做会怎样 |
| --- | --- |
| **金额换算成美元** | 15 种币种混池。`>50k` 档的历史达标率会从 **14.84% 虚高到 21.57%**（差 **6.6pp**），因为 JPY/MXN 这类"名义大、实际小"的项目被错放进高档 |
| **按时间切分，不随机** | 成功率逐年上升（2015 年 **33.59%** → 2024 年 **64.50%**）。随机切分等于让模型"偷看未来"，测试指标会虚高且无法复现 |
| **主指标用 AUC/PR-AUC/Brier/lift，不用准确率** | 2023+ 测试集多数类占 **64.41%**，"全猜成功"就能拿 64% 准确率；准确率无法反映排序能力 |
| **排除 10 个事后列** | 混入 3 个就会让测试 AUC 变成 **1.0000** 的假象（结果字段直接泄漏答案） |
| **时长用精确值** | 旧列用 `.dt.days` 截断，影响 **281,564 行（41.79%）**，分档端点附近会错组 |
| **文本长度改缺失感知** | 旧列把缺失文本算成 3 字符（标题 5 行、简介 47 行），长度特征被污染 |
| **履历严格 point-in-time** | 旧口径把"未来才发生的结果"算进历史，独立审核判为 Critical；修正后 `creator_prev_success_rate` 有 2,709 行取值变化 |

**场景**：一个测试期真实项目（Games，目标 **$5,852**、时长 **21 天**；标题匿名化）。

| 步骤 | 数字 | 取数对象（不可混用） |
| --- | ---: | --- |

### 4.3 解释性：黑盒怎么变得可讲（2026-11-08 新增）

HistGB **没有原生可解释性**（250 棵×≤31 叶 ≈ 7,750 个叶子值；sklearn 连 `feature_importances_` 都不提供）。我们用三层补上，产物见 `S1_解释性.md`。

**(1) 三模型同口径对比 —— 解释与精度分开**

| 模型 | ROC-AUC | PR-AUC | F1 | Brier | 相对 HistGB 的排序力 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 逻辑回归（完全可解释） | 0.8464 | 0.9056 | 0.8326 | 0.1507 | **95.9%** |
| 随机森林（150 棵） | 0.8749 | 0.9229 | 0.8513 | 0.1403 | 99.2% |
| **HistGB（最终）** | **0.8823** | **0.9295** | **0.8564** | **0.1316** | 100% |

⇒ 结论不是"只能用黑盒"，而是：**用 LR 讲方向与量级，用 HistGB 拿剩下 3.6pp 的精度**。

**(2) 置换重要性（测试集抽样 20,000，5 次重复，AUC 为准）**

| 特征 | 重要性（AUC 降幅） | 占比 |
| --- | ---: | ---: |
| `creator_previous_count` | 0.1229 | **43.3%** |
| `m_log_goal_usd` | 0.0559 | 19.7% |
| `creator_prev_success_rate` | 0.0257 | 9.1% |
| `prep_days` | 0.0256 | 9.0% |
| `subcategory_key` | 0.0183 | 6.4% |
| `m_dur_days_exact` | 0.0143 | 5.1% |
| `category_parent_name` | 0.0068 | 2.4% |
| `name_word_count` | 0.0045 | 1.6% |

前 8 项合计 **96.6%**；两组履历特征合计 **52.4%**——与"去履历掉 3.4pp AUC"的消融结论互相印证。**文本长度类特征合计不到 1%**（`m_blurb_len` 0.34%、`m_blurb_words` 0.37%、`m_name_len` 0.08%）。

**(3) LR 系数（数值特征，优势比 = 每 +1 标准差）**

| 特征 | 系数 | 优势比 | 读法 |
| --- | ---: | ---: | --- |
| `creator_previous_count` | +0.705 | **2.02** | 履历次数每 +1 SD，成功几率约翻倍 |
| `m_log_goal_usd` | −0.542 | **0.58** | 目标金额每 +1 SD，成功几率 ×0.58 |
| `m_blurb_len` | +0.372 | 1.45 | 简介字符数越多略正向（但与下一行相互抵消） |
| `m_blurb_words` | −0.411 | 0.66 | 简介词数越多略负向 |
| `creator_prev_success_rate` | +0.258 | 1.29 | 历史成功率越高越好 |
| `m_dur_days_exact` | −0.202 | 0.82 | 时长每 +1 SD，成功几率 ×0.82 |
| `prep_days` | +0.071 | 1.07 | 准备越充分略正向 |
| `yr` | +0.099 | 1.10 | 逐年上行（时间漂移，需时间切分） |

⚠️ 分类特征系数需谨慎：one-hot **未设参照组**（`drop` 默认 `None`）+ L2 收缩，系数是"相对平均水平的收缩偏离"，不能读成"相对某参照类别的对数几率"。分类特征建议只用于排序，不用于讲幅度。

**(4) 部分依赖曲线（PDP，边际形状）—— 三处修正了此前的口头结论**

| 特征 | PDP 首→尾 | 与 LR 符号 |
| --- | ---: | --- |
| `m_log_goal_usd` | 83.6% → 45.5%（**−38.1pp**） | 一致 |
| `creator_previous_count` | 58.0% → 88.7%（**+30.7pp**） | 一致 |
| `prep_days` | 48.6% → 69.6%（+18.4pp） | 一致 |
| `m_dur_days_exact` | 72.6% → 53.1%（−13.4pp） | 一致 |
| `m_blurb_len` | 63.2% → 66.0%（**+2.5pp**） | 一致 |
| `m_name_len` | 64.7% → 65.1%（+0.3pp） | 一致 |
| `creator_prev_success_rate` | 67.4% → 67.4%（**≈0**） | **不一致** |

三个值得写进报告的发现：

1. **"简介越长成功率越低（−13.3pp）"是构成效应，不是模型行为**：模型里 blurb 长度的边际效应是 **+2.5pp**，且重要性不足 1%。原始对比里那个负号来自品类/目标金额的构成差异。**此前的口头结论应撤回**。
2. **`creator_prev_success_rate` 是条件效应**：置换重要性 9.1%（很高）但 PDP 几乎平（≈0）⇒ 它的作用依附于其他特征（交互），单看边际看不出来。这正是"置换重要性 ≠ 方向"的标准案例。
3. **履历与目标金额是两条主梁**（52.4% + 19.7% = 72%），时长与品类是第二梯队，文本长度几乎不影响。

### 4.4 样本外实测与价值维度检验（2026-11-09 新增，回应"效果应在测试集取"）

**原则**：描述性基准可用全量，但必须标 **in-sample**；**任何"效果/验证"只来自测试期**（`yr≥2023`，n=100,469）；**ΔP 是模型反事实，不称实测效果**。

**(1) 450 格评分卡的样本外支撑度**

| 口径 | 可用格（n≥300） |
| --- | ---: |
| in-sample（全量 2009–2026） | **250 / 450** |
| **out-of-sample（仅测试期）** | **85 / 432** |

⇒ 必须如实写：**评分卡在样本外只有 85 格站得住**，其余格的"历史参照"是 in-sample 描述，不能当作未来预期。

**(2) 同一格 in-sample vs 样本外的差距**（85 个两边都 n≥300 的格）

- OOS − in-sample 达标率差：**中位 +7.37pp**，范围 −4.53 ~ **+28.23pp**；
- **37.6% 的格绝对差 >10pp**。

⇒ 印证审查意见"基准率漂移未处理"：训练期观测率会**系统性低估**近年成功率。

**(3) 价值维度单独检验（取代旧的"用成功率 CI 给价值定级"）**

判级规则：`最稳妥`/`应避免` 只认 **Δrate** 的 95% CI；`最高价值` 只认 **Δvalue** 的 95% CI（value = rate × 成功项目平均募资额），按 `creator_id` 整簇重抽 200 次。45 项检验：**推荐级 43 / 参考级 2**。

关键结论（这是双目标的实证，不是修辞）：

| 角色 | 代表例（design） | Δrate | Δvalue |
| --- | --- | ---: | ---: |
| 最稳妥 `<=1k×1-14d` | 达标率升 | **+19.4pp** [+16.3, +22.9] | **−$8,904** [−10,369, −6,826] |
| 最高价值 `>50k×31-45d` | 金额升 | −32.2pp [−34.7, −29.4] | **+$108,438** [+63,458, +193,892] |

⇒ **"最稳妥"提高达标率的同时显著压低价值**（art、comics、design 的价值 CI 全为负）；用成功率区间去给"最高价值"定级会掩盖这一点。`advice_by_category.*` 的旧评级已被 `s3_value_tests.csv` 取代，引用请用后者。

**(4) 取消项目敏感性**

| 任务口径 | 成功率 |
| --- | ---: |
| 二分类（排除取消 69,210 条） | **49.21%**（n=604,629） |
| 取消项目计入失败 | **44.16%**（差 **5.05pp**） |

⇒ 报告必须写明任务条件是"**最终进入成功/失败的项目**内的成功率"，而非"所有新项目的成功率"。
