# 选题说明（中期 / 提案口径）

**主题：众筹上线前的配置优化与成功率预测**
数据：Kaggle Kickstarter 全量项目（694,062 条 / 43 字段），清洗后可建模 604,629 条（successful + failed）

---

## 1. 商业问题：我们要产出什么

**产品形态：一个「上线前配置评分与优化建议」工具。**

- **输入**（发起人填写，全部是上线前已知信息）：品类、国家、目标金额、计划项目时长、标题与简介文案、是否二次发起。
- **输出**（三件）：
  1. **达标概率评分**：该配置在历史上的达标概率，并附同类配置的历史基准与样本量；
  2. **配置建议**：目标金额档位、项目时长、文案关键词的调整方向；
  3. **权衡视图**：不同目标金额档下「达标概率」与「成功时募资额」的取舍曲线。
- **决策人**：发起人（主）；平台（次，用于上线前的风险提示）。
- **明确不做**（提前写进 PPT，防被问倒）：
  - ❌ 不做**爆款预测**——43 个字段里没有任何流量 / 视频 / 社群 / 投放变量，爆款由受众与传播决定；
  - ❌ 不做**因果推断**——目标金额是发起人预判需求后自定的（内生性），我们只主张关联与预测；
  - ❌ 不给**人**打分（不给发起人做信用分），只给**配置**打分——84% 的发起人一辈子只发起一次。

## 3. 关键变量（已定）

### 3.1 目标变量：`succ`

| `state` 取值 | 行数（清洗后） | 处理 | 理由 |
| --- | ---: | --- | --- |
| `successful` | 297,538 | `succ = 1` | 达标 |
| `failed` | 307,091 | `succ = 0` | 未达标 |
| `canceled` | 69,210 | **保留在数据里，`succ` 记缺失** | 取消 ≠ 失败；作为独立第三类，可做稳健性检验或描述「取消率」 |
| `live` / `submitted` / `started` / `suspended` | 已删除 | — | 没有可用结果（右删失 / 被平台中止） |

> 所以成功率的分母是 **successful + failed = 604,629**，不是 673,839。

### 3.2 自变量（三组 + 文本 + 时间）

| 组 | 字段 | 性质 |
| --- | --- | --- |
| **可行动杠杆** | `log_goal`（目标金额）、`dur_days`（项目时长）、`name_clean` / `blurb_clean`（文案） | ✅ 给建议 |
| **条件变量** | `category_key`、`subcategory_key`、`country_final`、`location_type`、`currency` | 只用于给基准率 |
| **发起人履历** | `creator_rank`、`creator_n_projects`、`creator_prev_success_rate`、`is_relaunch` | 条件变量；`creator_prev_success_rate` 只用**该项目之前**的历史构造 |
| **时间** | `yr`（背景，用于时间切分）；`mon` / `dow` / `hour` | 仅描述，**不建议**（上线时点本身是选择结果，混杂严重） |
| **文本特征** | `blurb_clean` / `name_clean` 的 TF-IDF（3000 维） | 文案用词 |

### 3.3 必须剔除的 10 个泄漏列（放进模型 = 偷看答案）

`pledged`、`usd_pledged`、`backers_count`、`percent_funded`、`converted_pledged_amount`、`spotlight`、`profile_state`、`staff_pick`、`state_changed_at`、`profile_state_changed_at`

**演示（PPT 上值得留一格）**：把 `spotlight` / `staff_pick` / `profile_state` 加进结构化特征后，测试集 AUC 从 **0.8304 直接变成 1.0000**——不是模型变强，是答案泄漏。

## 4. 分析方法（已定）

| 阶段 | 具体方法 | 产出 | 课程周次 |
| --- | --- | --- | --- |
| **① 数据清洗** | 三层清洗 R1–R5 / V1–V8 / 25 派生列（已完成，有文档与审计） | `ks_clean.csv` | — |
| **② 描述性统计** | 分组成功率、分箱单调性、品类跳度、时间趋势、辛普森检查（品类内 goal 效应） | 基准率表与关键图表 | W1 |
| **③ 特征工程** | `log(goal)`、时长、年/月/星期、品类与国家独热、TF-IDF（blurb/name）、履历（仅历史） | 结构化矩阵（约 70 维）+ 文本稀疏矩阵 | W3 |
| **④ 特征选择 / 降维** | 方差与相关性过滤 → **L1 正则（LASSO）** 选变量 → **PCA** 降维；**RFE 仅作为结构化子集的可选方案**（在训练窗口内做交叉验证，避免选择泄漏） | 精简特征集 + 稳定性检验 | W3 |
| **⑤ 模型构建** | 逻辑回归（报**优势比**，可解释）→ 决策树 / 随机森林 / 梯度提升（比性能）→ 可选 KMeans 对「配置」分群 | 达标概率模型 + 配置分群 | W2 / W4 / W5 |
| **⑥ 双目标建模** | 对「成功时的募资额」做**分位数回归**（中位/90 分位），与达标概率组合成取舍曲线 | 配置评分表（含金额权衡） | W5+ |
| **⑦ 时序** | 月度达标率的 Holt-Winters / 指数平滑，并与朴素基准对比 | 平台层面趋势与预测 | W7 / W8 |
| **⑧ 模型评估** | **时间切分（训练 ≤2022 / 测试 ≥2023）**；指标 AUC / PR-AUC / Brier / 校准曲线 / 十分位 lift；对比 4 个基线（多数类、仅 `log_goal`、仅结构化、结构化+文本）；分年 AUC 曲线 | 评估报告 | W11 |
| **⑨ 结果解释与落地** | 配置评分表（品类 × 金额档 × 时长档，**只展示 n ≥ 300 的格子**）+ **按品类**的文案关键词面板 + 上线前清单 | 工具原型与建议清单 | W11 |

**三条验证纪律**（必须写进 PPT）：

1. **不准用随机切分**：成功率从 2015 年 33.6% 涨到 2024 年 64.5%，随机切分等于把未来信息混进训练；
2. **不准把 accuracy 当主指标**：2023 年后的测试集里多数类基线就是 **0.6441**，"全猜成功"就有 64.4% 准确率；主指标用 AUC / PR-AUC / 校准 / lift；
3. **特征选择与调参必须在训练窗口内完成**（含 RFE、PCA），否则就是另一条泄漏通道。

## 5. 商业洞察与边界

**预期结论方向**

1. 目标金额是**阈值型**杠杆：≤$1k 达标率 84.4% → >$500k 仅 32.3%，且品类内同样成立；
2. 项目时长**非单调**：8–21 天最好（70.9% / 67.9%），46–60 天塌到 28.4%；
3. 品类是最强的结构性差异（Comics 74.8% vs Journalism 27.4%）；
4. 发起人履历是最强单一信号（首次 40.7% → 11 次以上 95.4%）——属**平台侧**信号，不能写成"多发起几次"；
5. 文案「写什么」远胜「写多长」：只用长度 AUC 0.4764，用 TF-IDF 0.7354，且**增量因品类而异**（Technology +0.16，Film & Video +0.02）；
6. **双目标权衡**（Games 示例）：目标越高，达标率越低，但成功时中位募资越高（≤$1k 时 $1,797 → >$50k 时 $119,325）——所以建议不是"越低越好"。

**边界声明（放在显眼位置）**：本项目基于观察性数据，`goal` 由发起人预判需求后自定，存在内生性；因此所有结论均为**关联与预测**，**不构成因果效应**。平台标记（`staff_pick` / `spotlight`）仅作关联描述，不作因果解释。

**三个预备问答**

| 可能被问 | 回答 |
| --- | --- |
| "变量里没有流量，怎么谈爆款？" | 我们不做爆款预测，只做上线前配置优化；流量类变量确实不在数据里 |
| "目标金额是你自己定的，因果说不清" | 承认内生性，全篇只主张关联与预测 |
| "品类和履历改不了，算什么建议？" | 区分可行动杠杆（金额/时长/文案）与条件基准（品类/国家/履历） |
