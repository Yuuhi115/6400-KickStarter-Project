## 二、方法（写报告可直接用）

### 2.1 数据三层

```
原始 694,062 × 43   (454.9 MB, Kaggle: domingosun/kickstarter-dataset-629147-projects-may-2025, MIT)
  ↓ 清洗（三层规则，已有）
清洗 673,839 × 81   (43 原始 + 38 派生；删除 20,223 行 = 2.91%)
  ↓ 建模就绪（本项目新增）
建模 673,839 × 92   (新增 11 个 m_* 列)
附录 USD-only 460,596 × 92（稳健性检验用）
```

**11 个建模列的用途**

| 列 | 解决什么 |
| --- | --- |
| `m_goal_usd` / `m_log_goal_usd` | 金额统一换算美元（非 USD 占 31.26%；不换会让 >50k 档达标率高估 6.6pp） |
| `m_goal_usd_ok` / `m_goal_usd_filled` / `m_currency_usd` | 标记可用性（含 USD 缺汇率的 7,836 行精确填充） |
| `m_dur_days_exact` | 精确时长，修正旧 `.dt.days` 截断（影响 41.79% 行） |
| `m_name_len` / `m_blurb_len` / `m_blurb_words` | 文本长度缺失即 NA（旧列把缺失算成 3 字符） |
| `m_split` | 预置时间切分（train ≤2022 / test ≥2023） |
| `m_is_modelable` | 可建模掩码（canceled 不算失败） |

### 2.1.1 92 列的构成（43 + 38 + 11）与文件格式

| 组成 | 列数 | 内容 |
| --- | ---: | --- |
| 原始字段 | **43** | 数据集自带（`collected_at` … `usd_type`），全部保留 |
| 清洗派生列 | **38** | 25 个旧清洗派生（时间 7、品类/地区 4、文本 5、金额 3、标签 2、履历 4）＋ 13 个修订新增（三个汇率列各 `_raw`/`_zero_usd_fixed`/`_invalid` 共 9 个，加 `creator_prior_projects`、`creator_history_known_results`、`creator_history_unavailable`、`creator_history_scope`） |
| 本项目新增 | **11** | §2.1 表中的 `m_*` 列 |
| **合计** | **92** | 673,839 行 × 92 列 |

**文件格式与位置（重要：92 列只有 parquet，没有 CSV）**

| 产物 | 格式 | 行 × 列 | 体积 | 路径 |
| --- | --- | --- | ---: | --- |
| 清洗数据（输入） | CSV | 673,839 × **81** | 710 MB | `01_清洗数据/ks_clean.csv` |
| **建模就绪（最终使用）** | **parquet** | 673,839 × **92** | **231 MB** | `08_建模就绪数据/ks_model_ready_v1.parquet` |
| USD-only 附录 | parquet | 460,596 × 92 | 144 MB | `08_建模就绪数据/ks_model_ready_usdonly.parquet` |

读取方式：

```python
import pandas as pd
df = pd.read_parquet(r"08_建模就绪数据/ks_model_ready_v1.parquet")   # 673,839 × 92
```

三条要点：

1. **没有 92 列的 CSV**：导成 CSV 约 730 MB，且可空布尔/时间列会退化成字符串；parquet 保留类型且体积约为 CSV 的 1/3。
2. **92 列 ≠ 92 个特征**：实际入模 **18 个**（见 2.2）。其余是：标识符与 URL（`id`、`creator_id`、`profile_*_id`、各种 `_url`）、**10 个事后/泄漏列**（仅用于描述统计）、**9 个汇率审计列**（元数据）、以及若干冗余列（`goal_capped ≡ goal`、`creator_n_projects ≡ creator_rank`、`static_usd_rate_raw ≡ static_usd_rate`）。
3. 数据本体**不在 git、也不在进度包 zip 里**（231 MB 发不了），zip 只含 `README_建模数据说明.md` 与两个 `build_report*.json`；需要数据时可跑 `_build_model_ready.py` 重建，或走云盘传 parquet。

### 2.2 特征（18 个，全部上线前可得）

- 数值 13：`m_log_goal_usd`、`m_dur_days_exact`、`prep_days`（上线−创建）、`yr`、`mon`、`launch_quarter`、`dow`、`m_name_len`、`m_blurb_len`、`m_blurb_words`、`name_word_count`、`creator_previous_count`（=rank−1）、`creator_prev_success_rate`
- 类别 5：`category_parent_name`、`subcategory_key`、`country_final`、`location_type`、`currency`
- **排除的 10 个事后/泄漏列**：`pledged`、`usd_pledged`、`backers_count`、`percent_funded`、`converted_pledged_amount`、`spotlight`、`profile_state`、`staff_pick`、`state_changed_at`、`profile_state_changed_at`

### 2.3 建模与验证

| 环节 | 设定 |
| --- | --- |
| 模型 | Dummy(prior) 基线、逻辑回归（liblinear, 3000 iter）、随机森林、**HistGB**（lr 0.08 / 250 iter / 31 leaves / l2 1.0） |
| 切分 | **按时间**：train ≤2020（443,693）/ val 2021–2022（60,467）/ test ≥2023（**100,469**）；另做过复刻组员的 ≤2019/2020–22/>2022 口径对照 |
| 阈值 | 只在**验证集**上用 181 点网格最大化 F1 → 0.39；原样套测试集 |
| 主指标 | ROC-AUC、PR-AUC、Brier、校准曲线、十分位 lift、分年稳定性；**准确率只作参考**（测试集多数类 64.41%） |
| 泄漏纪律 | 排除事后列；`goal` 内生 → 全程只主张关联，不做因果 |

### 2.4 三个决策轴的可操作化

```
business value = P(达标) × 同格「成功时中位募资」            ← 募资额代理（无收入/成本字段）
intervention   = max over {目标金额档, 时长档} [P(改后) − P(当前)]   ≥15pp 高 / 5–15 中 / <5 低
risk           = (1 − P) × 同格「成功时中位募资」；另标高危高赔格（达标率<10% 且 中位募资>$50k）
```

### 2.5 为什么这么做（每个关键决定都配一个反例）

| 决定 | 如果不这么做会怎样 |
| --- | --- |
| **金额换算成美元** | 15 种币种混池。`>50k` 档的历史达标率会从 **14.84% 虚高到 21.57%**（差 **6.6pp**），因为 JPY/MXN 这类"名义大、实际小"的项目被错放进高档 |
| **按时间切分，不随机** | 成功率逐年上升（2015 年 **33.59%** → 2024 年 **64.50%**）。随机切分等于让模型"偷看未来"，测试指标会虚高且无法复现 |
| **主指标用 AUC/PR-AUC/Brier/lift，不用准确率** | 2023+ 测试集多数类占 **64.41%**，"全猜成功"就能拿 64% 准确率；准确率无法反映排序能力 |
| **排除 10 个事后列** | 混入 3 个就会让测试 AUC 变成 **1.0000** 的假象（结果字段直接泄漏答案） |
| **时长用精确值** | 旧列用 `.dt.days` 截断，影响 **281,564 行（41.79%）**，分档端点附近会错组 |
| **文本长度改缺失感知** | 旧列把缺失文本算成 3 字符（标题 5 行、简介 47 行），长度特征被污染 |
| **履历严格 point-in-time** | 旧口径把"未来才发生的结果"算进历史，独立审核判为 Critical；修正后 `creator_prev_success_rate` 有 2,709 行取值变化 |

## 四、已有结果（`11_结果与报告/`）

### 4.1 端到端案例（先读这个，5 分钟就能明白工具怎么用）

**场景**：一个美国创作者，准备在 **Games** 品类发起项目，目标 **$10,000**、时长 **30 天**、首次发起。

| 步骤 | 用什么 | 结果 |
| --- | --- | --- |
| ① 给这个配置打分 | `model_histgb_ours.joblib`（18 特征） | 预测达标概率 **59.3%** |
| ② 找它的历史参照 | 评分卡 `config_scorecard_usables.csv`（格 = 10–20k × 15–30d） | 该格 n=6,519，历史达标率 **53.6%**（95% CI 52.4–54.8），平均预测 65.7%，校准基本吻合 |
| ③ 看该格的收益潜力 | `decision_axes_cells.csv` | 成功时中位募资 **$33,360** → 期望募资额 **E ≈ $21,923**，风险分 **$11,437** |
| ④ 看该格能改多少 | 同上，`dp_max` + 建议动作 | 干预潜力 **+26.3pp**（high 档），建议动作：**目标 → ≤1k 档、时长保持 15–30 天** |
| ⑤ 看改完的代价 | 对照 `<=1k × 15–30d` 格 | 概率升到 **96.5%**（历史 85.0%，n=15,355），但成功时中位募资只有 **$1,862** → **E 从 $21,923 掉到 $1,798（−92%）** |
| ⑥ 所以怎么提建议 | 双目标权衡 | 不能只说"降目标更好"，要写清："提到达标概率的代价是期望募资额下降 92%；若你更看重金额，可考虑 20–50k × 15–30d（P 61.9%、E ≈ $53,232）" |

**这个案例说明了三件事**：① 模型给的是概率而不是判决；② 概率要配历史基准才有意义（59.3% 在 53.6% 的格里只是"略好于平均"）；③ 任何"提高成功率"的建议都必须带上金额代价。

## 六、文本层：TF-IDF 构建与入模对比（2026-11-12 完成）

> 产物：`12_文本层_TFIDF/`（10 脚本 / 16 个结果文件 / 6 图 / 4 报告 / 2 个可部署模型 + 独立加载模块，共 47 个文件）；工作区 `13_TFIDF文本层_v2/` 保留中间产物、12 组 test 预测与并入校验脚本。
> 详版：`12_文本层_TFIDF/04_报告/results_text_layer.md`；**报告第 6 章可直接粘贴**：`04_报告/report_section_中文.md`；演示要点：`04_报告/slides_bullets.md`。

### 6.1 做了什么

* **文本源**：`name_clean + " " + blurb_clean`（与 `11_工作计划/期末计划_v2.md` S1.1 一致）。blurb 是 Kickstarter 卡片简介（中位 119 字符 / 19 词，最长 239 字符），不是完整 campaign 描述；空 name 5 行、空 blurb 13 行，TF-IDF 记零向量。
* **TF-IDF**：`max_features=3000, min_df=20, stop_words='english', ngram_range=(1,2), sublinear_tf=True, strip_accents='unicode', lowercase=True`，**只在 train（443,693 行）拟合**。
* **两种表示**：① 稀疏 3,000 维直接拼 226 维基座 → LR（3,226 列）；② TF-IDF → TruncatedSVD(128, rs42) → HistGB / RF（354 列）。
* **12 次拟合一次跑完**：{HistGB, LR, RF} × {全样本, USD} × {基线, +文本}；不重调超参、不换切分、val 只选阈值、test 只看一次。
* **评估**：ΔAUC / ΔAP / ΔBrier + **按 `creator_id` 整簇 bootstrap 1,000 次**（对应组员规约②），并行列级 i.i.d. 对照；另做决策影响（阈值穿越、top-10% 重合、|Δp| 分位）。

### 6.2 先证基线，再谈增量

| 门 | 结果 |
| --- | --- |
| **G0 数据门** | 21 项断言全通过：三段 443,693 / 60,467 / 100,469、两两不交、并集 604,629；USD 327,642 / 33,542 / 54,435；非 USD 测试行 46,034；与 `02_数据切分/split_assignment.parquet` 行级一致率 `split_ours` = **1.000000**、`is_usd` = **1.000000** |
| **G1 基线复现** | 6 个基线用同款超参重训，与 `03_模型文件/*_schema.json` 对账，**最大偏差 7.7e-5**（容差 1e-4）；唯一差异是 `hgb_full` 的 val 阈落在 0.380（发布 0.390，F1 平坦区相邻网格点） |
| **与 v1 交叉验证** | #7 = **0.8847304345**（v1 0.884730）、#9 = **0.8553698211**（v1 0.855370），1e-6 级一致 |

### 6.3 结果（test，n=100,469）

| 配置 | 特征数 | AUC | AP | Brier | ΔAUC（creator 整簇 95%CI） | ΔBrier |

### 6.4 三条必须一起引用的限定

1. **区间结论**：HistGB 的 +0.24pp 与 LR 的 +0.90pp 在 **creator 整簇**与**行级 i.i.d.** 两种 bootstrap 下**都显著、区间几乎重合**（i.i.d. 分别为 [+0.185,+0.297]pp、[+0.767,+1.013]pp）。2026-11-12 晚修复了 i.i.d. 分支的权重对齐 bug（旧值 [−0.023,+0.518]pp / p=0.074 已作废，点估计不变），修订记录见 `12_文本层_TFIDF/04_报告/results_text_layer.md` §4.3。
2. **RF 的负增益只讲方向**：v1 打乱对照（SVD 列在行间随机打乱后重训）显示 RF 仍降 0.994pp、HistGB 仅降 0.104pp，支持「128 维稠密特征稀释分裂候选」这一机制方向；但打乱对照**不能给出百分比**，不要写「78% 来自稀释」。
3. **文本层不是长度特征的重复**：分组置换重要性中 `text_svd_128` = 0.0128，高于时长（0.0126），而 `m_name_len` 0.00018、`m_blurb_words` 0.00025 几乎为 0。

### 6.5 与 S1 验收线的冲突（需组会拍板）

`11_工作计划/期末计划_v2.md` 的 S1 验收线是「TF-IDF 增量 ≥ +0.02 AUC」。在 18 特征基线已达 0.8823 的前提下：

* 本次最强配置（LR + 稀疏）也只有 **+0.90pp**，主配置 HistGB **+0.24pp**；v1 在 250 棵 RF、LR+SVD 等更多组合上同样没超过 +1pp；
* 履历（52.4%）+ 目标金额（19.7%）已占置换重要性的绝大部分，文本的增量空间远小于 +2pp；
* **结论：本次 12 个配置均未达到 +0.02 AUC**，按 S1 约定「否则作为附录」处理；这不是实现问题（基线与 v1 都对齐到 1e-5～1e-6）。

如需改口径，建议改为「ΔAUC > 0 且 95%CI 排除 0 + 决策影响可解释」；或明确把文本层定位为**解释素材**（关键词面板、简介长度与达标率的描述性关联）。是否修改属组内决策，报告按现行 S1 写「未达、入附录」，不自行改判定标准。

### 6.6 对下游决策的影响

主配置 vs 基线：top-10% 名单重合 8,341 / 10,047（Jaccard **0.710**，约 17% 换人）；**约 4.1% 测试行判定翻转**（上调 2.1% / 下调 2.1%，共同阈值 0.39 下 2,051 / 2,098；若各自沿用验证集阈值 0.395 / 0.380，则为 1,628 / 2,521，即上调 1.6% / 下调 2.5%；两套口径都在 `02_结果/decision_flips.csv`）；单项目 |Δp| 中位 **2.23pp**、p99 **18.94pp**（最大 45.76pp）。产品化时必须标「模型版本 + 分数变化说明」。
